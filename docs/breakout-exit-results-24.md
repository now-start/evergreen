# 실험 24 — 빠른 청산 결과

## 결론

24시간 청산 후보는 채택 기준에 미달했다. 기본 수익 중앙값만 보면 개선되지만,
대응 구간 수익 차이는 악화됐고 비용 스트레스에서 이점이 사라졌다. 빠른 청산만으로
위험 중단을 해결하지 못했다. 운영 전략은 변경하지 않는다.

## 공통 조건과 결과

실험 23과 동일한 22개 연속 구간, 36,384시간(계획의 88.97%)이다.
각 구간에 원금 100만 원을 따로 배정했다. 아래 수익은 구간별 순수익률의 중앙값이며
한 계좌의 누적·연환산 수익이 아니다. 원래 돌파의 4비용 ×22구간 전체 결과 재현이 일치했다.
이미 탐색한 자료를 사용한 규칙 청산 실험이며 딥러닝 추가 학습이나 새 홀드아웃은 없다.

| 조건 | 기존 48시간 수익 | 후보 24시간 수익 | 후보−기존 대응 차이 중앙값 | 후보 최악 낙폭 |
|---|---:|---:|---:|---:|
| 기본 | +2.00% | +2.40% | −0.378%p | 10.72% |
| 슬리피지 2배 | +1.11% | +0.33% | −0.080%p | 10.45% |
| 수수료·슬리피지 2배 | +0.19% | −0.11% | 0.000%p | 10.72% |
| 체결 1시간 지연 | +1.69% | +1.90% | −0.223%p | 11.08% |

기본 조건의 양수 구간은 12→14개, 자연 청산(종료 정산 제외)은 69→91회,
위험 중단은 4→3구간이다. 하지만 비용 2배에서는 후보의 양수 구간이 10/22개이고
위험 중단은 5구간이다. 모든 조건의 사전 기준을 통과하지 못했다.

22개 모의 계좌, 총 배정 원금 2,200만 원 기준 기본 비용 합계:

| 항목 | 기존 | 후보 |
|---|---:|---:|
| 비용 차감 순손익 | +1,189,519원 | +903,108원 |
| 수수료 | 75,691원 | 97,586원 |
| 슬리피지 비용 | 151,383원 | 195,174원 |

후보의 합산 순손익 차이는 −286,411원이다. 매매 횟수와 비용이 늘었으며, 청산 변경은
이후 진입·보유 경로도 바꾸므로 이 차이 전부를 수수료 또는 특정 거래 하나의 효과로 단정하지 않는다.
빠른 청산 뒤 재진입이 반복되는지와 큰 추세 수익을 놓치는지를 다음 진단 대상으로 남긴다.
24시간보다 더 짧은 기간을 같은 자료에서 즉시 탐색하지 않는다.

후속 사후 진단에서 기본 조건의 종료 정산 포함 거래 수는 기존 72회, 후보 94회였다.
같은 계좌에서 직전 매도 체결 후 24시간 이내 재매수한 거래는 기존 2건(비수익 1건,
합계 +1,008원), 후보 7건(비수익 6건, 합계 −84,295원)이었다.
수수료 포함 체결 손익을 기존 `trade_pnl`로 대사한 분류다. 표본이 매우 작고 경로가 다르므로
24시간 재진입 제한의 효과를 입증하지 않는다. 다음 실험을 설계할 근거로만 사용한다.

## 재현 및 검증

- [사전 계획 및 명령](breakout-exit-experiment-24.md).
- 출력 `outputs/breakout-exit-24`, 실행 종료 코드 0, 입력 SHA 재확인 통과.
- 22구간 ×4비용 ×4후보/대조 =352개 백테스트. `prior`는 기존 돌파의 중복 대조다.
- 기존 돌파의 전체 결과(체결·자산 곡선 포함) 88개가 실험 23과 일치했다.
- 현 봉 저점 제외, 다음 시가·지연 체결, 기본 48시간 보존, 필터 경로 일치,
  잘못된 후보/기간 거부, 대조 재현 불일치 시 실패 기록을 테스트했다.
- 전체 테스트 350개 통과, 테스트용 MariaDB 미설정 22개 제외, 커버리지 89.32%.
  Ruff 검사·포맷, mypy 63개 소스 검사, `git diff --check` 통과.
- 사용 가능한 Spark 모델의 읽기 전용 독립 CLI 리뷰 결과 APPROVE, 조치 필요 발견 없음.
  리뷰는 코드·설계 승인이지 수익성 기준 통과가 아니다.
- 실거래·Config Server·DB·배포·버전·커밋·푸시 변경 없음.
