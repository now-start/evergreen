# 실험66 — 조기 돌파의 장기 평균 상승 방향

## 실행 전 계약

실험65 후속 계획의 후보 `liquidation-buffer-entry84-slope168` 하나를 실행한다.
신규 진입에는84시간 고점×1.001 초과와 함께 현재 봉을 제외한 이전168봉 평균이
24시간 전의 이전168봉 평균보다 엄격히 높아야 한다.65의 종가>평균 조건은 결합하지 않는다.

신호 인덱스s에서 종가[s−168:s]와 종가[s−192:s−24] 합을 비교한다.
신호 봉은 양쪽에서 제외한다. 초기 신호도 현재 봉+과거192봉이 필요하므로
최소 준비 데이터193봉을 요구한다. 비교 계좌는 기존처럼200봉을 사용한다.
신호 이후 미래 데이터는 사용하지 않고, 보유 청산에는 새 조건을 적용하지 않는다.

실험57의 청산·진입 예산·채널 리셋·위험 우선순위, 같은22개 연속 계좌·원금100만원,
기본/슬리피지2배/비용2배/지연1시간 네 조건을 유지한다. 결측 보간 없음.
대조군은 원 돌파·현금·50·57·64·65이며 이전528개 전체 JSON이 정확히 일치해야 한다.
후보 포함616개 체결 손익과 최종 자산을 대조한다.

통과 조건: 네 조건 모두 원 돌파 대비 대응 수익률 차이 중앙값>0, 수익 계좌 과반,
최대 낙폭≤10%, 중단0; 기본 자연 청산10건 이상.57·64·65 대비 차이도 보고한다.
자료는 이미 관측한 탐색 구간이며 새 미관측 검증이 아니다. 통과해도 자동 승격하지 않는다.
실거래·Config Server·DB·배포·버전은 변경하지 않고, 리뷰는 사용자 지시에 따라 생략한다.

## 재현

```sh
.venv/bin/python -m evergreen.research.experiments.breakout_entry_window \
  --slope-filter \
  --raw data/regime-08-2020-2026-public \
  --reference outputs/breakout-entry-trend-filter-65-verified \

```

초기9개 테스트가 미구현 옵션·실행기를 검출한 RED를 확인했다.

옵션 동시 활성 금지, 대조군 변조 거부를 검증한다.

### 실제 계좌 경로의 이익·손실

기본 조건에서64 대비 손익이 크게 나빠진 계좌는005(−248,674원),
011(−198,150원),003(−86,038원)이다. 개선 계좌는000(+130,090원),
021(+112,777원),017(+50,299원)이다. 시각과 거래는 저장된 전체 JSON에서 확인했다.

- 000에서는 조기 반등 손실을 피하고 기존02-01·02-04 진입으로 돌아가 위험 중단을 피했다.
- 반면005 등 주요 상승 구간의 진입을 놓치거나 늦춰, 전체적으로 그 이익을 상쇄하지 못했다.
  005의02-14 진입은02-16으로 늦어졌고,03-13·03-29 진입은 없어졌다.
- 기본·비용2배·지연은 중단0이지만 슬리피지2배001에서 한도 초과가 남았다.
  해당 계좌를 mark 관찰기로 재실행해 원래 전체 JSON·곡선과 대조했다.
  최초 초과는2022-05-05 16:00 UTC 종가의 보유 가격 하락이며, 낙폭10.9810%였다.
  기준가격48,037,000원·BTC0.01978167 보유 상태로 당시 체결 비용은0이었다.

**결론:** 평균의 방향을 추가하면 개선될 것이라는 가설도 지지되지 않았다.
84시간 진입에 비슷한 추세 필터를 계속 결합하거나 임계값을 재검색하지 않는다.

## 후속 실험67 사전 계획 — 실험57의 고정4시간 진입 평가 간격

검증: 집중40개 통과(3.98초), 전체809개 통과·격리 MariaDB 미설정22개 건너뜀
(247.98초), Ruff·포맷·mypy72개 소스·diff 공백 검사 통과.
보유 중 평균이 하락하는 fixture의 초기 가격 배열이 실제 하락을 만들지 못한 것을
테스트가 검출해 가상 과거 가격만 보완했다. 전략 조건이나 결과 기준을 바꾸지는 않았다.
연구·위험 재현·전체 테스트 프로세스 모두 정상 종료. 커밋·푸시·운영 변경 없음.

57의168시간 고점 진입으로 돌아간다. 새 후보 `liquidation-buffer-entry4h`는
고점 창이나 추세 필터가 아니라 **신규 진입 평가 간격 하나**만 바꾼다.

- 현재 확정 시간봉의 종료 시각이 UTC00/04/08/12/16/20시일 때만 기존57 진입 조건을 평가한다.
  나머지 시간에는 신규 매수를 예약하지 않는다. 건너뛴 신호를 나중에 강제 실행하지 않고,
  다음 허용 시각에 그때의 최신 확정 자료로 다시 계산한다.
- 이는 시간봉 신호의4시간 간격 평가이며4시간 OHLC로 데이터 전체를 바꾸는 실험이 아니다.
  기존26의 연속 두 종가 확인 조건도 추가하지 않는다. 시간대 위상이나2/6/12시간 간격을 검색하지 않는다.
- 가설은 짧게 나타났다 사라지는 돌파에 반응하는 횟수를 줄이는 것이다.
  반례는 유효한 빠른 추세를 놓치거나 더 불리한 가격에서 진입하는 것이다.
- 실제 매수는 기존 다음 시가, 지연 조건에서는 추가1시간 후다. 보유 청산·위험 평가·기존
  대기 주문 실행은 계속매시간 수행한다.57의 진입 예산·채널 리셋·청산 버퍼는 유지한다.
- 84시간·가격 위치·평균 방향 필터는 모두 사용하지 않는다. 원금100만원·같은22개 계좌·
  준비봉200·네 비용/지연 조건·공통 원 돌파 기준 게이트는 유지한다.
- 원 돌파·현금·50·57의352개 전체 JSON을66 결과와 대조하고 후보 포함440개 손익을 검증한다.
  UTC경계·초기 신호·지연 체결·비허용 시각 청산·기존 기본값 재현을 테스트한다.
- 탐색 기간을 이미 관측했으므로 특정 시각의 우연한 유리함일 가능성을 명시한다.
  통과해도 새 미관측/전진 검증이 필요하며 실거래·설정·DB·배포는 변경하지 않는다.
