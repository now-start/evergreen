# 실험53 — 보유 연장 후24시간 중간 점검

## 실행 전 계약

실험52에서 고정한 후속 계획을 실행한다. 같은 공개2020~2026 자료 중 기존2022년
이후22개 평가 계좌·36,384시간을 유지하고 초기 자금100만원, 전액 매수/매도,
수수료·슬리피지·1시간 추가 지연·영구 계좌 위험 중단 조건을 바꾸지 않는다.

정책50의 실제 진입 예산과 짧은 추세 청산을 사용한다. 한 포지션의 첫 추가 청산
결정에서51의 긴 추세도 청산이면 매도한다. 긴 추세는 아직 청산하지 않으면 현재
포지션만 긴 추세 청산으로 연장하고, 원래 결정 종가와24시간 뒤 점검 시각을 고정한다.

연장 중 초기 손절·48봉 채널·계좌 위험 청산이 먼저 발생하면 그대로 처리한다.
계속 보유하여 점검 시각에 도달했을 때 확정 종가가 원래 결정 종가 이하이면 다음
시가(+지연)에 청산한다. 더 높으면 이후 긴 추세 청산을 유지하며 다시 점검하지 않는다.
이는24시간 최대 보유 제한이 아니다. 예약 주문은 이후 반등으로 취소하지 않고,
점검 청산의 최소 주문 거절은 실제 청산까지 다음 봉에 재시도한다.

분기·점검 상태는 다음 실제 매수/매도에서 초기화하지만 계좌 고점·자금·위험 중단은
유지한다.52번의 사후 레이블로 분기를 선택하지 않으며 새 계좌 경로 전체를 계산한다.

기존 breakout-v1·50·51 대조를 같은 네 조건으로 재생하고 전체 JSON 재현성을 확인한다.
후보는 기존 대비 블록별 중앙값 개선, 절반 초과 양수 블록, 최대 낙폭10% 이내,
영구 중단 없음, 기본 조건 정상 청산10건 이상을 모두 만족해야 한다.
24시간 외 다른 점검 주기를 탐색하지 않는다. 이미 본 데이터의 탐색 결과이며 미래
미관측 검증·실거래 승격으로 해석하지 않는다. 독립 리뷰는 사용자 요청으로 생략한다.

## 실패 원인

24시간 점검은 주요 위험 중단을 막지 못했다. 기본003·비용2배005·지연003은
51과 전체 결과 JSON이 같았다. 반면, 하루 안에 원래 결정 가격을 회복하지 못했으나
이후 상승한 거래가 먼저 청산됐다.

- 기본011: 2024-03-04 매수 후51은3월15일04시,99,104,000원 시가에 팔아
  109,625.22원 이익이었다.53은3월7일06시,92,885,000원 시가에 팔아26,195.01원
  이익으로 줄었다. 다른 거래는 같고 이 차이로 해당 계좌가83,430.21원 악화됐다.
- 기본021: 2026-08-19 매수 후51은8월28일17시,108,251,000원에 팔아
  139,237.02원 이익이었다.53은8월24일05시,105,409,000원에 팔아109,743.55원
  이익으로 줄었다. 해당 계좌 차이는−29,493.47원이다.
- 기본017: 2025-09-10 매수의 조기 청산으로 해당 거래 이익이17,686.46원에서
  9,208.50원으로 감소했다. 이후9월29일 매수에는 줄어든 잔고가 투입되어 계좌 전체
  차이는−9,176.18원으로 더 커졌다. 거래별 손익 차이와 계좌 전체 차이를 분리해야 한다.
- 지연014: 2024-12-04 매수의 청산이12월9일에서12월7일로 빨라져 이익이

  계좌 차이는−2,807.84원이다.

이 시각들은 UTC다. “하루 안에 회복하지 않으면 연장이 불리하다”는 이번 규칙은
관찰 자료에서 지지되지 않았다. 이를 근거로12시간·48시간 등 여러 점검값을
추가 탐색하지 않고, 이 후보는 보관 후 기각한다.

## 재현성과 검증

실행 명령:

```sh
.venv/bin/python -m evergreen.research.experiments.breakout_exit_checkpoint \
  --raw data/regime-08-2020-2026-public \
  --reference outputs/breakout-entry-stop-trend-context-51 \
  --output outputs/breakout-exit-checkpoint-53
```

`backtest`의 연구 전용 점검 옵션과 공통 평가기를 사용한다.52의 사후 레이블을
읽거나 학습한 모델은 없다.53 실행의 대조는 가격·비용·체결·자산 경로를 포함한
기존/50/51 ×4조건 ×22계좌, 총264개 전체 JSON 일치로 검증했다.
원래22계좌·36,384시간·88.97% 커버리지를 유지한다.
입력533개·공개 원본321개·소스67개 해시를 재검사했고, 전체528개 결과의 모든 체결
손익 합계와 최종 자산 차이가0.000001원 이내 일치했다. 미완결/수량 불일치 거래는 없다.

신규17개와52회귀16개, 총33개 테스트가 통과했다(14.45초). 구현 전 신규 최초11개의
실패를 확인했다. 정확한24시간 경계/종가 동률, 회복 후 점검 소진, 예약 후 반등,
거절 후 재시도, 위험 주문 대체, 다음 실제 매수의 상태 초기화와 잔고 유지,
호환되지 않는 옵션 거절 및 대조 결과 변조 시 실패 처리를 검증한다.
전체661개 통과·22개 건너뜀(300.20초), 커버리지88.36%로80% 기준을 충족했다.
건너뛴 항목은 일회용 MariaDB가 설정되지 않은 통합 테스트다. Ruff·198파일 포맷·
mypy67개 소스·`git diff --check`도 통과했다. 테스트 통과와 수익성 게이트 통과는
별개이며, 후보의 수익성 게이트는 네 조건 모두false다.

## 후속 실험54 사전 계획 — 연장 시작 시 저점 상승 확인

53의 사후 시간 점검은 제거한다. 다음에는 연장 결정을 내리는 순간의 가격 구조를
확인한다.50의 첫 추가 청산에서 긴 추세가 아직 청산하지 않고, **직전24봉 저점의
최솟값이 그 이전24봉 저점의 최솟값보다 높을 때만** 현재 포지션을51 방식으로 연장한다.
동률이나 더 낮은 저점이면50대로 청산한다. 현재 결정 봉은 두 비교 구간에서 제외한다.

가설은 긴 평균 추세가 남아 있더라도 단기 저점이 이미 낮아지는 구간의 불필요한
연장을 줄일 수 있다는 것이다. 확인된 미래 손익·52레이블은 사용하지 않는다.
24시간 길이와 엄격한 `>` 비교를 고정하며 파라미터 탐색을 하지 않는다.

진입·계좌 예산·초기 손절·원래48봉 채널·위험 중단·실제 체결 후 리셋은 그대로다.
연장 조건은 현재 포지션의 첫 추가 청산에 한 번만 판단한다. 청산 주문이 거절되더라도
같은 포지션을 새 연장 사건으로 보지 않으며 기존 청산 신호 재평가·위험 절차를 유지한다.
미래 재진입과 수량 변화를 포함하는 새 연속 계좌 경로를 평가한다.
기존/50/51 대조와 동일 네 조건/22계좌/수익·위험 기준을 유지한다.

54는 이 문서 시점에는 계획만 고정했으며 구현·실행하지 않았다.53은 수익성 목표를
달성하지 못했으며 실거래·설정 서버·DB·배포·버전·커밋은 변경하지 않는다.
