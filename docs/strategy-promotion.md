# 단일 전략 승격 준비

결정일: 2026-09-10. 상태: **후보 고정 / 실거래 승격 차단 / 전진 페이퍼 미실행**.

## 1. 선택

준비 후보는 **`breakout-buffer-early3-v1` 한 개**다. 실험72 `early3`를 가리키는
동결 후보 식별자이며, 현재 운영 registry·Config Server에 등록된 전략 ID는 아니다.
학습 모델이 아닌 규칙 전략으로, 재학습·모델 파일·시드 선택이 필요하지 않다.

실험71의57 완화형 `wide20`을 비교 기준으로 유지한다. 실험72에서 최근 네 조건 중
최저 합산 손익이 가장 높았고, 과거 최저 합산 손익도 소폭 늘었다. 그러나 이것은
두 구간·모든 조건에서 우월하거나 전체 실험 중 통계적으로 최적인 전략이라는 뜻이 아니다.
최근 1시간 지연은 악화됐고 과거 개선은 단일 계좌에 의존한다. 후보 선택은
다음 검증 대상을 좁히는 결정이지 미통과 게이트를 통과 처리하는 결정이 아니다.

## 2. 고정 계약

실행 근거: `research.experiments.buffer_improvement.POLICIES["early3"]`와
`research.experiments.relaxed_exits.simulate(..., "liquidation-buffer", ...)`.
동결 구현 기준 커밋은 `bd83796`이다. 후속 이식은 이 커밋과 실험72 소스 해시를
기준으로 회귀 비교하며, 후보 설정을 변경하면 같은 후보 버전을 재사용하지 않는다.
연구 결과의 `strategy=regime-mlp-v1` 표시는 재사용된 라우터 이름이다. 이 후보는
모든 진입 허용 점수를 상수로 넣으며 MLP 추론·장세 선택을 하지 않는다.

| 항목 | 고정 값·동작 |
|---|---|
| 시장·봉 | 업비트 KRW-BTC 현물, 확정1시간봉, UTC, 준비200봉 |
| 자금 | 계좌별 가상100만원, 원화/BTC 전액 전환, 레버리지·분할 없음 |
| 진입 | 현재 종가 > 이전168봉 고가 최대 ×1.001; 현재 봉은 채널에서 제외 |
| 초기 손절 | 실제 진입 시가 −6×원래 매수 신호 이전24봉 평균 TR |
| 수익 추적 시작 | 진입 후 확정 종가 고점 ≥ 진입 시가 +3×진입 TR |
| 추적 거리 | 6×max(진입 TR, 현재 봉 이전24봉 평균 TR); 청산선 하향 금지 |
| 추세 유예 | 이전24봉 평균 종가 > 그 전24봉 평균이면 수익 추적 청산 유예; 초기 손절은 유지 |
| 이탈 확인 | 손절/추적 조건의 연속2봉 이탈 확인 |
| 채널 청산 | 현재 종가 < 이전96봉 저가 최솟값 |
| 재진입 | 추가 청산 후 조건부48시간 저점 채널 리셋 대기;96시간 청산 채널과 별개 |
| 진입 예산 | 초기 손절가의 비용 차감 예상 자산이 계좌 고점80% 이상일 때만 진입 |
| 선제 청산 | 현재 종가−(1+추가 지연 봉 수)×이전24봉 TR의 비용 차감 자산이 고점80% 이하이면 예약 유지 |
| 계좌 중단 | 평가 자산이 보존된 고점 대비20% 이상 하락하면 영구 중단; 체결 갭으로 초과 손실 가능 |
| 모의 체결 | 신호 다음 시가; 지연 조건은 추가1시간. 같은 신호 종가 체결 금지 |
| 기본 비용 | 매수·매도 각각 수수료0.05%, 슬리피지0.1%; 최소5000원·수량1e-8 |
| 대조 조건 | 기본 / 슬리피지2배 / 수수료·슬리피지2배 / 추가1시간 지연 |

20%는 **연구 후보의 중단 기준**이며 운영 한도 변경 승인이 아니다. 현재 운영
`TradingSettings.max_drawdown`의 상한10%는 유지한다. 수수료·최소 주문 등은
실거래 시 실제 거래소 응답으로 다시 확인해야 하며 연구 값을 그대로 사용하지 않는다.

## 3. 동결 근거

전체 결과와 한계: [실험72](buffer-improvement-72.md).
최근22계좌36,384시간, 과거13계좌14,889시간의 부분 수집 자료다.
최근 평가 끝은2026-09-01 UTC, 과거는2018–2019년이며 그 사이 모든 기간을
끊김 없이 검증한 것이 아니다. 다른 실험에서 본 최근 자료도 미관측 검증으로 재사용하지 않는다.

| 합산 순손익(각100만원 독립 계좌) | 최근 | 과거 |
|---|---:|---:|
| 기본 | 1,630,112원 | 1,468,521원 |
| 네 조건 중 최저 | 1,403,923원 | 1,403,846원 |
| 기본 wide20 대비 | +27,597원 | +3,064원 |
| 지연 wide20 대비 | -8,541원 | 0원 |
| 네 조건 최대 낙폭 | 13.68% | 19.12% |

`outputs/buffer-improvement-72/`의 아래 SHA-256을 고정한다. 자료를 복사할 때
실제 파일과 검증하고, `inputs.json`의 절대 경로는 원본 환경 기준임을 고려한다.
산출물을 이 저장소에 포함시키거나 원격 보관소로 업로드하지 않았다.

| 파일 | SHA-256 |
|---|---|
| protocol.json | `d21279a77f310c6416c25335ec9525fad6bb449242681fbaa31309ffe53f2238` |
| results.json | `f6e3cb36deb961e7a80c82c07b045e4f121d04e6182a340c02df27cf2d8cdb74` |
| artifacts.json | `27242e01812a8daf30d859fe58a01707d384db0ec7ebda706aa8fb00c2d32831` |
| inputs.json | `7717c3cd35e2686e0bbac9ee2d6e4e60dd3e3ea9498d4c7f4a5b4aa73536dcb4` |
| status.json | `3a3577682442f4d32a5c40d909ca6b74119bdb3383698f23cf1fed26616f52b1` |

420개 대조 전체 JSON 재현·980개 손익 대사가 통과했다. `protocol.json`에는
커밋 전 dirty 소스 해시가 기록돼 있으므로 커밋 후 HEAD가 달라도 소스 해시로 대조한다.
재실행은 선행71·데이터67/70를 확보한 후 새 출력 경로로만 수행한다.

```sh
uv run python -m evergreen.research.experiments.buffer_improvement \
  --root outputs --output outputs/buffer-improvement-72-recheck
```

이 명령은 과거 백테스트 재현이며 실시간 페이퍼 시작 명령이 아니다.

## 4. 구현 전에 해결할 운영 차이

| 현재 소스 | 후보를 실행하기 위해 필요한 작업 |
|---|---|
| `trading/engine.py`는 원래 돌파 `target()` 직접 호출 | 후보의 순수 상태 전이와 운영 주문 실행을 분리하고 백테스트와 같은 전이를 공유 |
| `trading/state.py`는 계좌·주문 중심 상태만 저장 | 후보 ID/버전, 진입 기준/TR, 추적 고점/청산선, 연속 이탈 수, 리셋 대기, 청산 예약과 신호 시각 영속화 |
| 운영은 실시간 호가, 연구는 다음 시가 | 신호/체결 기록 분리, 실제 지연·호가와 연구 비용 가정의 차이를 측정; 같은 체결이라고 주장하지 않음 |
| 운영 낙폭 상한10%, 후보 연구20% | 독립적인 위험 변경 검토·명시 승인 전 운영 설정 변경 금지 |
| 거래 원장에 후보 포지션 정보 없음 | 기존 BTC 임의 인수·상태 초기화 금지; 잔고·미체결 대사 및 명시적인 전환 절차 필요 |

실거래 워커 내부에 연구 실행기를 바로 붙이지 않는다. 현재 단계에서는 DB migration,
운영 전략 ID, Config Server, GitOps, 주문 루프를 변경하지 않았다.

## 5. 다음 단계와 통과 조건

1. **공통 상태 전이 이식 및 재현**: 확정봉·실제 모의 체결 이벤트를 입력으로 하는
   후보 상태를 분리한다.35계좌×4조건의 신호·체결·거절·자산 결과가 기존72와
   일치해야 한다. 기존 `breakout-v1`도 회귀 통과해야 한다.
2. **복구·멱등성 검증**: 봉 중복/누락, 재시작, 청산 예약 중 장애, 부분 체결,
   주문 응답 유실, 외부 잔고 변경, 다중 워커에서 중복 주문0·대사 불일치0을 요구한다.
   상태를 잃으면 현금 계좌로 간주하지 않고 중단한다.
3. **전진 페이퍼**: 실제 주문 권한 없이 별도 가상 원장으로 실행한다. 실행 시작
   다음 완성 봉부터를 검증 구간으로 고정하며 이미 관찰한 데이터로 소급 시작하지 않는다.
   후보·wide20·원래 운영 돌파를 동시에 비교하고 같은 실제 도착 데이터/지연을 기록한다.
   최소90일과 후보 자연 청산10회 모두 충족 전 성과 판정하지 않는다. 기간 중
   임계값 변경 시 새 후보 버전과 새 검증 구간으로 다시 시작한다.
4. **수익·위험 승인**: 기존72의 최근/과거·네 조건 전체 개선 게이트 실패를
   그대로 기록한다. 전진 페이퍼 통과만으로 이 실패를 지우지 않는다. 유지할 기준은
   기존 문서대로 대응 중앙값·양수 계좌 과반·낙폭·중단·거래 수를 함께 본다.
   페이퍼 단일 계좌는 기존35계좌 게이트를 대체하지 않는다. 후보 변경이나 기준
   변경이 필요하면 사전 재설계·새 미관측 평가와 사용자 승인 없이 승격하지 않는다.
5. **실거래 전환은 별도 작업**: 통과 증거·실제 운용 금액·손실 한도·전환 시각을
   명시적으로 확정한 뒤에만 릴리스/CI/GitOps/Config Server 전환을 준비한다.

페이퍼 관찰 항목은 후보 버전, 마지막 확정봉, 데이터 신선도, 신호 원인, 모의 체결
지연/비용, 보유 상태, 청산 예약, 자산/낙폭 및 중단 이유다. 아직 대시보드·상시
페이퍼 프로세스를 구축하거나 이90일 검증을 시작하지 않았다.

## 6. 중단·복귀

현재는 운영을 바꾸지 않았으므로 후보 준비 취소가 기존 거래에 영향을 주지 않는다.
향후 후보 운영 중 장애가 나면 신규 매수를 막고 미체결·보유·원장을 대사한다.
후보 포지션을 보유한 채 예전 코드로 되돌리면 추적 상태가 사라지므로 자동 전환하지 않는다.
검증된 후보 상태 복구 또는 승인된 청산·현금 상태 확인 후에만 이전 아티팩트와
설정으로 복귀한다. 주문 예약·미체결이 있는 동안 두 전략을 동시에 가동하지 않는다.
