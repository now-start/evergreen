# 실험57 — 청산 가능 자산에 변동 여유 적용

## 실행 전 계약

56에서 고정한 가설을 검증한다.50의 진입 예산·짧은 추세 확인·초기 손절·적응 추적·
채널 재진입 제한을 그대로 두고 보유 중 선제 청산만 추가한다.53~55의 연장 규칙은
사용하지 않는다. 보유 중 확정 종가에서 다음 값을 계산한다.

```text
기준 가격 = max(0, 종가 − (1 + 추가 지연 봉 수) × 현재 봉 제외 직전24봉 평균 TR)
청산 가능 자산 = 현금 + BTC × 기준 가격 × (1 − 매도 슬리피지) × (1 − 매도 수수료)
```

청산 가능 자산이 보존된 계좌 고점의90% 이하이면 `signal` 매도를 예약한다.
다음 실제 시가(+0/1시간 추가 지연)와 비용으로 전액 청산한다. 이론적 기준 가격에
실제 체결시키지 않는다.1봉 평균 변동은 고정 가정이며 위험 한도 보장이나 미래 가격
예측이 아니다. 계수·창 길이 검색을 하지 않는다.

예약 후 반등·최소 주문 거절에도 의도를 유지하고, 실제 체결 시에만 포지션 예약
상태를 초기화한다. 이미 있는 전략 매도의 체결을 뒤로 미루지 않는다. 계좌 잔고·
고점·위험 영구 중단은 보존한다. 실제10% 초과 시 기존 위험 우선순위가 적용되며,
56에서 발견한 위험 주문 교체 시 추가 지연은 이번 실험에 섞어 수정하지 않는다.

평가 계약은 기존22개 계좌·각100만원·36,384시간·200봉 워밍업과 기본/슬리피지2배/
비용2배/체결1시간 지연이다. 기존/50/51의 전체 결과를 재현한다. 기존 및prior 대비
계좌 수익률 차이 중앙값>0·양수 계좌 절반 초과·최대 낙폭10% 이내·위험 중단0개·
기본 정상 청산10개 이상을 유지한다. 네 조건을 모두 통과해야 탐색 후보 통과다.

자료는 이미 관찰한 탐색용이며 새 미관측 검증이 아니다. 실거래·Config Server·DB·
배포·버전·커밋은 변경하지 않는다. 독립 리뷰는 사용자 요청대로 생략한다.

```sh

  --liquidation-buffer \
  --raw data/regime-08-2020-2026-public \
  --reference outputs/breakout-entry-stop-trend-context-51 \
  --output outputs/breakout-liquidation-buffer-57
```

종료0, `completed_partial_coverage`, `live_enabled=false`다. 전체 기간 무결성 통과가
아니라 기존 결측 없는 평가 구간88.97%를 사용했다. 기존/50/51 ×22계좌×4조건의
264개 전체 JSON이 일치한다.528개 체결 손익 합과 최종 자산 차이가0.000001원 이내
일치했고, 최종 BTC·매수/매도 수량 불일치는 없다. 입력533개·원본321개·소스68개
해시를 재검사했다.

구현 전 신규11개 실패를 확인한 뒤 모두 통과했다(8.32초). 공통 실행기·56의 관찰

## 후속 실험58 사전 계획 — 긴 추세51과 같은 청산 여유의 조합

57의 예방 청산 자체는 네 조건에서 중단을 없앴지만50의 수익 한계가 남았다.
다음에는51의 긴 추세 맥락에 **동일한** 청산 여유 규칙을 적용한다. 이는50/51을
사후 장세별로 골라 쓰는 정책이나53~55의 포지션별 연장 분기가 아니다. 이전 추세
구간만24에서168봉으로 고정한51 경로 전체에 선제 청산을 적용한다.

현재 봉 제외24봉 TR·`1+추가 지연 봉 수`·비용 차감·계좌 고점90%·예약 래치·
거절 재시도·채널 재진입·영구 위험 중단은57과 동일하게 둔다. 값 검색이나 위험
주문 교체 지연 수정은 섞지 않는다. 긴 추세 수익을 남기면서 한도 초과를 줄일 수
있다는 가설이며, 선제 청산이 그 추세 이익까지 끊을 수 있다는 반대 가설도 유지한다.

기존/50/51/57과 동일22계좌·네 조건·기존 수익/위험 게이트를 비교한다. 기존 대조
및57 전체 결과의 재현성을 확인하고, 주요 계좌뿐 아니라 전체 경로를 재평가한다.
58은 여기서는 계획만 고정했으며 아직 구현·실행하지 않았다. 수익성 목표는 미달성이다.
