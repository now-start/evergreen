# 매매 전략 V0

상태: V0 연구 명세 및 오프라인 구현 기준. 작성일: 2026-09-07.

아래 내용은 초기 연구 명세다. 이후 사용자 선택으로 고정한 현재 주력 검증 후보는
[168시간 고점 돌파](breakout-strategy.md)이며, 초기 SMA 기준선과 구분한다.

수익이 검증된 전략이나 실거래 활성화 승인이 아니다. 공개 데이터 수집, 품질 검사,
단순 전략·공통 백테스트와 [MLP/CNN 오프라인 학습](deep-learning-experiment-03.md)은
`evergreen.research`에 구현했다. 아래 V0의 4시간 예측 과제와 별도로 실험 03은
12시간 비용 초과 확률을 시험하며, 운영 정책으로 확정한 것은 아니다.
상시 Paper는 미구현이며, 별도 [주문 실행기](trading-execution.md)는 비활성화 상태로 제공한다.
실행 방법과 실제 데이터 검증 한계는 [리서치 가이드](offline-research.md)를 따른다.

## 1. 범위와 결정 상태

| 항목 | 내용 | 상태 |
|---|---|---|
| 시장 | 업비트 `KRW-BTC` 현물, 레버리지·공매도 없음 | 사용자 선택 |
| 운용 방식 | 원화 또는 BTC 보유, 전략적 분할 매수·매도 없음 | 사용자 선택 |
| 원금 | 시작 시 가용 원화 전액을 운용 대상으로 사용할 수 있음 | 사용자 허용 |
| 비교 | 단순 추세추종과 딥러닝을 동일 평가 체계에서 비교 | 사용자 선택 |
| 자동화 | 후보 학습부터 평가·승격까지 자동, 미통과 후보는 배포하지 않음 | 사용자 요구 |
| 판단 주기 | 확정된 1시간봉마다 판단 | V0 가설 |
| 기준 전략 | SMA 20/60, 진입 이격 0.2%, 청산 이격 0% | V0 가설 |
| 손실 중단 | 운용 평가금의 고점 대비 10% 하락 | 임시 안전 기준 |
| 딥러닝 과제 | 향후 4시간 수익과 하락 위험 추정 | 후속 실험 가설 |

V0 수치들은 최적화 결과가 아니다. 특히 10%는 손실을 보장하는 상한이 아니며,
급락·체결 지연·슬리피지·거래소 장애로 이를 넘는 손실과 원금 손실이 가능하다.

### 자금 경계

- 운용 시작 시 미체결 주문과 잠긴 원화를 확인한 후, 가용 원화로 원금을 확정한다.
- 기존 보유 BTC는 임의로 매도하거나 봇 자산에 편입하지 않는다.
- 추가 입금의 자동 증액은 V0 범위 밖이다. 봇 원장과 거래소 잔고를 구분한다.
- 외부 수동 거래·출금으로 원장과 잔고가 어긋나면 신규 진입을 중단하고 대사한다.
- 전액 매수에도 수수료, 주문 금액·수량 정밀도에 따른 잔액은 남을 수 있다.
- 사용자가 정한 최소 투자금은 없지만, 거래소의 최소 주문 조건은 반드시 만족해야 한다.

## 2. 데이터 계약

입력은 업비트의 해당 시장 OHLCV 수치이며, 차트 이미지·뉴스·다른 거래소 가격은
첫 실험에서 사용하지 않는다. 확보 가능한 기간을 수집하되 모든 과거 자료를 한꺼번에
학습시키지는 않는다. 학습 기간과 검증 기간은 분리한다.

| 필드 | 의미와 제약 |
|---|---|
| `market` | `KRW-BTC` |
| `interval_minutes` | `60` |
| `open_time` | UTC, 시간대 포함, 정각; 캔들 구간의 시작 |
| `close_time` | `open_time + 1시간`; 구간은 시작 포함·끝 제외 |
| `open`, `high`, `low`, `close` | 양수·유한한 KRW 가격, 원본 정밀도 보존 |
| `volume` | 음수가 아닌 유한한 BTC 거래량 |
| `quote_volume` | 음수가 아닌 유한한 KRW 거래대금 |
| `fetched_at` | UTC 수집 시각, 원본 응답과 함께 추적 |

정제 파일은 JSONL이다. `close_time`은 `open_time + 1시간`으로 계산하며 중복 저장하지 않는다.

기본 키는 `(market, interval_minutes, open_time)`이다. 같은 키의 가격·거래량·거래대금
값이 동일하면 중복 제거하고, 이 값들이 충돌하면 평가용 데이터셋 생성을 중단한다.
`fetched_at`과 원본 응답은 별도 수집 이력으로 보존하며 중복·충돌 비교에서 제외한다.
`low <= min(open, close) <= max(open, close) <= high`를 검증한다.

수집·정제 규칙:

1. 분 캔들 API의 `unit=60`, `market=KRW-BTC`를 사용한다. 응답은 정렬해 사용한다.
2. 요청당 최대 200개이며, 다음 요청의 `to`는 확보한 가장 오래된 시작 시각으로 잡는다.
   경계 중복을 제거하고 커서가 과거로 이동하지 않으면 오류로 처리한다.
3. 아직 닫히지 않은 캔들은 전략 입력에서 제외한다. 수집 시각이 늦었다고
   과거 실시간에 그 데이터가 이미 도착했다고 가정하지 않는다.
4. 누락 시간대는 임의 전방 채움이나 0 거래량 캔들로 합성하지 않는다. 업비트는
   체결이 없는 구간에는 캔들을 생성하지 않으므로 누락만으로 장애라고 단정하지 않는다.
5. 재조회 후에도 설명되지 않는 누락은 품질 보고서에 기록한다. V0 백테스트는
   명시된 평가 기간에 공백이 있으면 실패시키며, 손실 구간을 조용히 제거하지 않는다.
   현재 수집기는 첫 품질 실패를 보존하고 종료한다. 재조회는 별도 새 출력 디렉터리로
   실행하며 실패한 데이터셋을 덮어쓰거나 자동으로 공백을 메우지 않는다.
6. 연속된 60개 확정봉 전에는 SMA 기준 전략이 주문 신호를 만들지 않는다.
7. 저장한 원본과 정제 데이터에 기간·행 수·결측·중복·해시를 기록한다.

캔들 생성 조건·페이지 크기·`to` 경계는 [업비트 분 캔들 API](https://docs.upbit.com/kr/reference/list-candles-minutes)를 따른다.
수집기는 요청 제한과 응답 헤더를 존중하고, 제한 응답을 빈 데이터로 취급하지 않는다.
인증키 없는 공개 데이터 수집부터 구현한다.

## 3. 기준 전략: `sma-trend-v0`

시점 `t`의 확정 종가를 `C[t]`라고 할 때:

```text
fast[t] = 최근 20개 확정 종가의 산술평균
slow[t] = 최근 60개 확정 종가의 산술평균
gap[t]  = fast[t] / slow[t] - 1
```

| 보유 상태 | 조건 | 목표 행동 |
|---|---|---|
| 원화 | `gap[t] > 0.002` | 가용 운용 원화로 전액 매수 |
| 원화 | `gap[t] <= 0.002` | 원화 유지 |
| BTC | `gap[t] < 0` | 봇 보유 BTC 전액 매도 |
| BTC | `gap[t] >= 0` | BTC 유지 |
| 모든 상태 | 위험 중단 상태 | 신규 진입 금지, 청산·대사 우선 |

단발성 교차 이벤트가 아니라 현재 추세 상태를 판단한다. 따라서 워밍업 종료 시점에
이미 진입 조건을 만족하면 진입할 수 있다. 진입과 청산 사이의 구간은 잦은 왕복 거래를
줄이기 위한 가설이며, 0.2%가 거래 비용을 회수한다는 의미는 아니다.

- 같은 캔들은 한 번만 처리하고, 같은 방향 신호가 반복되어도 추가 주문하지 않는다.
- 미확정 주문이 있으면 새 전략 주문을 제출하지 않는다.
- 별도 익절, 물타기, 고정 보유 시간, 4시간봉 필터는 첫 기준 전략에 추가하지 않는다.
- 신호는 완성된 봉까지만 사용한다. 그 봉의 종가로 이미 체결됐다고 계산하지 않는다.
- 시간당 판단과 별도로 향후 Paper/Live에서는 잔고·주문·위험을 지속 감시한다.

## 4. 공통 백테스트 계약

### 체결과 비용

봉 `t`가 닫힌 뒤 정한 행동은 `t+1`의 시가를 기준으로 모의 체결한다.
이는 지연 없는 시장 체결의 보장이 아니라 OHLCV 기반 근사다. 실제 수집·추론·주문
지연 때문에 다음 시가를 놓칠 수 있으므로, Paper에서 체결 차이를 측정하고
추가 한 봉 지연 시나리오도 별도로 평가한다. 마지막 봉에서 생긴 신호는 실행하지 않는다.

```text
모의 매수가 = 다음 시가 × (1 + 매수 슬리피지율)
모의 매도가 = 다음 시가 × (1 - 매도 슬리피지율)
매수 주문 금액 상한 = 가용 운용 원화 / (1 + 매수 수수료율)
매수 BTC = 주문 금액 / 모의 매수가        # 주문 정밀도에 맞게 내림
매도 후 원화 증가 = 매도 BTC × 모의 매도가 × (1 - 매도 수수료율)
```

수수료는 매수·매도 각각 적용한다. 매수 후 원화에서는 실제 주문 금액과 수수료를
차감하고 정밀도에 따른 잔액을 보존한다. 주문 금액이 최소 조건 미만이면 체결시키지
않으며 사유를 기록한다. 전량 매도가 불가능한 잔량은 삭제하지 않고 잔고에 남긴다.

실험에는 매수·매도 수수료율, 슬리피지율, 최소 주문 금액, 주문 정밀도를 명시적으로
입력해야 한다. 미지정 값을 0으로 대체하지 않는다. 업비트의 현재 수수료·주문 조건은
[주문 가능 정보 API](https://docs.upbit.com/kr/reference/available-order-information)에서 확인할 수 있다.
현재 조건을 과거 전체에 적용했다면 역사적 실제 조건이 아닌 실험 가정이라고 표시한다.

기본 비용 시나리오 외에 슬리피지 2배, 수수료와 슬리피지 모두 2배, 추가 한 봉
체결 지연을 시험한다. 지연은 진입·전략 청산·위험 청산에 적용한다. 마지막 정산은
실제 주문이 아닌 공통 평가 시점의 비용 처리이므로 별도 지연하지 않는다.
주문 크기가 커도 고정 슬리피지로 전량 체결되는 근사에는 한계가
있다. 실자금 규모의 유동성·호가 검증 없이 백테스트 통과만으로 Live를 활성화하지 않는다.

### 손실 중단과 평가금

```text
E[t] = 봇 원화 + 봇 BTC × 현재 평가 가격
H[t] = max(초기 원금, 지금까지의 E)
DD[t] = 1 - E[t] / H[t]
```

V0 봉 백테스트는 시가의 주문 체결 후와 종가에서 평가금을 관측한다. `DD >= 0.10`을
확인하면 중단 상태를 고정하고 다음 봉 시가에 청산을 예약한다. 이후에는 재진입하지 않는다.
손실을 정확히 10%로 잘라 보고하거나 봉 저가에서 즉시 체결됐다고 가정하지 않는다.
중단 이후 잔여 평가 기간도 원화 상태로 보고서에 포함한다.

시가 청산 전에 추가 하락하거나 비용이 발생하면 실제 최대 낙폭은 10%보다 커진다.
봉 내부 손실 경로는 1시간 OHLCV만으로 복원할 수 없다. 따라서 이 결과로 실시간
위험 감시를 검증했다고 주장하지 않으며, Live 전에 더 세밀한 가격·체결 재생 검증이 필요하다.

고점과 중단 상태는 재시작·일자 변경·모델 승격으로 초기화하지 않는다. 원화/BTC는
전략 상태일 뿐, 실제 주문에는 제출 중·결과 불명·미체결·부분 체결·취소 중 상태가 별도로 필요하다.
실거래 청산은 미확정 주문과 잔고를 먼저 대사하고, 통신 단절 시 체결을 추측해 재주문하지 않는다.

### 공정한 비교와 지표

- 현금 유지, 매수 후 보유, `sma-trend-v0`, 향후 모델 전략을 비교한다.
- 모든 전략에 동일 원금·평가 시작/종료 시각·비용 시나리오를 적용한다. 평가 전 데이터는
  워밍업에만 쓰며, 평가 시작은 후보 성과를 본 뒤 바꾸지 않는다.
- 매수 후 보유는 평가 시작 시가에 매수한다. 이 기준에는 10% 중단을 적용하지 않아
  순수 보유 결과로 표시하고, 위험이 다른 비교 대상이라는 점을 보고한다.
- 평가 종료에 남은 BTC 중 주문 가능한 수량은 최종 종가에 매도 비용과 슬리피지를
  적용해 모의 정산한다. 최소 주문·정밀도로 매도할 수 없는 잔량은 보존한다.
- 공식 최종 평가금은 `정산 후 원화 + 미매도 BTC 잔량 × 최종 종가`이며, 수익률은
  `최종 평가금 / 초기 원금 - 1`이다. 이 평가금도 고점·최대 낙폭 계산에 포함한다.
  미매도 잔량에는 가상의 매도 비용을 차감하지 않는다. 정산 후 원화와 잔량 평가액을
  각각 표시하고, 잔량 평가액은 즉시 현금화할 수 있는 금액이라고 해석하지 않는다.
- 종료 정산은 연구용 평가이며 전략 신호가 아니다. 정산 비용도 최종 수익률·최대 낙폭에
  반영하고, 정산으로 닫힌 거래는 별도 표기하여 전략의 자연 청산 횟수와 구분한다.
- 필수 지표: 비용 차감 수익률, 최대 낙폭, 평가금 곡선, 총 수수료, 총 슬리피지 비용,
  자연 청산 왕복 거래 수, BTC 노출 시간 비율, 위험 중단 여부, 주문 거부·데이터 오류 수.
- 현재 `natural_exits`는 종료 정산을 제외한 전략·위험 매도 횟수다. 전량 모의 체결만
  지원하므로 왕복 종료와 일치하며, 이후 부분 체결 엔진에서는 거래 묶음별로 집계해야 한다.
  노출 비율은 시가 주문 처리 후 BTC가 남아 있는 평가 봉의 비율로, 잔량 보유도 포함한다.
- 체결 건별 시간·근거 봉·가격·수량·비용·잔고를 남긴다. 무거래는 오류나 성공으로
  단정하지 않고 0회로 보고하며, 승률처럼 분모가 없는 지표는 `N/A`로 표시한다.

### 재현성과 미래 정보 차단

실험마다 데이터 해시, 코드 커밋, 전략 버전, 파라미터, 비용 가정, 원금, 평가 기간,
난수 시드(모델 사용 시)를 기록한다. 보고서를 덮어써 실패 실험을 숨기지 않는다.

모델 평가는 시간순 워크포워드로 한다. 첫 제안은 학습 12개월·튜닝 3개월·평가 1개월을
한 달씩 이동하는 방식이다. 자료가 부족하면 기간을 몰래 줄이지 않고 평가 불가로 보고한다.
독립 테스트용 마지막 90일은 튜닝에 사용하지 않으며, 한 번 본 뒤에는 다시 미관측
테스트라고 부르지 않는다. 반복 자동 승격은 새로 축적된 미관측 구간을 사용한다.

4시간 예측 레이블은 해당 결과가 확정된 뒤에만 학습에 사용한다. 학습·튜닝 경계와
튜닝·평가 경계에서 레이블의 미래 구간이 다음 구간에 겹치는 표본을 제거한다.
스케일러·결측 처리·특징 선택은 학습 구간에만 맞춘다. 겹치는 윈도는 독립 표본으로
간주하지 않으며, 단순 시간 분할만으로 모든 누수가 해결된다고 주장하지 않는다.

시간순 분할은 [scikit-learn TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)을 참고한다.
후보를 반복 탐색하면서 우연히 높은 성과를 고르는 위험 때문에 실험 횟수와 실패도
보존한다. [백테스트 과최적화 연구](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

## 5. 학습·Paper·Live의 후속 경계

```text
확정 데이터 → 후보 학습 → 시간순 백테스트 → 고정 모델 Paper
                                                  │
                                       승격 기준 전부 통과
                                                  ↓
                                          Live 모델 교체
```

- 학습 주기는 우선 하루 1회 후보 생성으로 검토한다. 새 확정 데이터가 부족하면 건너뛴다.
- Paper는 모의 주문이고, 평가 대상의 모델·전처리·전략 파라미터는 고정한다.
  다른 후보 학습은 별도로 가능하지만 평가 중인 모델의 가중치는 바꾸지 않는다.
- 운영 모델과 후보를 같은 관찰 기간·초기 자금·비용 가정에서 나란히 Paper 평가한다.
- 최초 관찰 하한은 30일과 자연 청산 20회 모두 충족하는 안으로 검토한다. 이는 통계적
  신뢰성을 보장하는 표본 수가 아니며, 부족하면 계속 관찰하고 억지로 승격하지 않는다.
- 승격에는 비용 스트레스, 순수익·낙폭 기준, 운영 모델 대비 개선 기준, 다중 실험에 따른
  통계적 판정, 데이터·주문 오류 검사를 모두 포함한다. 구체적인 판정식은 후속 설계다.
- 판정식이 미정인 지금은 자동 승격 불가다. 향후에는 사전에 고정한 기준을 자동으로
  적용하며 사람이 후보마다 수동 승인해야 하는 흐름을 만들지 않는다.
- 최초 Live에는 비교할 운영 모델이 없으므로 별도의 최초 진입 기준이 필요하다.
  기준 미충족·후보 없음이면 원화 대기한다. 운영 모델이 있어도 위험 중단 상태가 우선이다.
- 모델 교체는 주문 처리와 분리하며 미확정 주문이 없는 안전한 경계에서 수행한다.
  모델 버전 변경은 계좌 포지션·원장·고점을 리셋하지 않는다.
- API·데이터 장애 때 신규 진입은 중단한다. 신뢰 가능한 주문·잔고·가격 정보가 있으면
  위험 축소 청산을 허용하고, 정보가 없으면 무작정 시장가 재주문하지 않는다.

모델 구조, 데이터 저장소, 실거래 체결 방식, 일중 위험 감시 간격, 중단 후 재개 정책은
아직 선택하지 않았다. 이를 임의의 코드 기본값으로 채워 실거래를 시작하지 않는다.

## 6. 구현 순서와 완료 판정

1. 이 명세의 데이터 계약과 기준 전략을 검토한다.
2. 공개 캔들 수집·정제·품질 보고서와 오프라인 기준 전략 백테스트를 구현한다.
3. 실제 데이터로 기준선·비용 스트레스 결과를 비교한 뒤 모델 과제와 승격 판정식을 확정한다.
4. 후보 학습과 고정 모델 Paper를 구현한다. 거래소 주문 권한은 요구하지 않는다.
5. 미확정 주문 대사·단일 실행자 보장·복구·위험 중단 검증을 마친 뒤 Live를 별도 도입한다.

오프라인 구현의 필수 테스트:

- 역순 응답 정렬, 중복·충돌·누락, 미완성 봉 제거, 페이지 경계 커서 정체.
- 워밍업 부족, 진입 임계값과 청산 임계값의 동일값 경계, 반복 신호와 미확정 주문.
- 미래 봉을 바꿔도 이전 신호·체결이 바뀌지 않음, 마지막 봉 신호 미체결.
- 매수 수수료 포함 전액 계산, 양방향 비용, 잔돈·최소 주문 미달·잔량 보존.
- 동일 캔들의 수집 시각만 다른 재조회는 중복, OHLCV 변경은 충돌로 판정.
- 종료 시 최소 주문 미달 BTC만 남으면 매도 비용 없이 `원화 + 잔량 × 종가`로 평가.
- 종가 중단 후 다음 시가 급락, 원금 대비가 아닌 고점 대비 낙폭, 재진입 금지.
- 마지막 평가 시점의 정산 비용·잔량·무거래와 동일 구간의 기준선 비교.
- 미래 레이블 경계 제거와 학습 데이터에만 맞춘 전처리(모델 단계).

성공 기준은 데이터가 재현되고 계산이 검증되는 것이다. 합성 데이터 테스트 통과나
좋은 백테스트 수익률을 실거래 수익의 증거로 보고하지 않는다.
