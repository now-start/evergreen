# 실험 27 — 같은 봉 거래량 확인

## 사전 계획

실험 26은 확인을 기다린 진입이 다수 구간에서 악화되고 지연 스트레스에도 약했다.
이번에는 기다리지 않고 현재 확정 돌파 봉의 거래량으로 진입을 거른다.
기존 기본 비용 거래 72건의 사후 진단에서 직전 24봉 평균 거래량을 초과한 거래는
70건(수익 32건, 기존 손익 합계 +1,152,746원), 나머지는 2건(수익 1건,
+36,773원)이었다. 변별력이 낮다는 반증이며 이 집계는 필터 적용 후 수익이 아니다.
그럼에도 계좌 경로 변화를 확인하는 단일 기각 실험을 수행하고 배수·기간을 탐색하지 않는다.

- 후보 `volume-24h`: 현재 확정 봉 BTC 거래량 > 직전 24개 봉 BTC 거래량 산술평균.
  현재 봉은 평균에서 제외한다. 같으면 차단하며 과거 평균이 0이면 현재 양수만 허용한다.
- 기존 현재 봉 168시간 고점 ×1.001 돌파 조건도 동시에 요구한다. 다음 시가 체결이며
  추가 지연 스트레스에서는 한 시간 더 늦는다. 거래량 필터 자체의 추가 대기는 없다.
- 원래 48시간 저점 청산, 10% 영구 위험 중단 트리거, 전액 매매 유지.
  실제 낙폭은 다음 시가 체결 및 비용으로 10%를 초과할 수 있다.
  실험 24~26의 빠른 청산·재진입 대기·연속 돌파는 혼합하지 않는다.
- 실험 26과 원자료 SHA·36,384시간/22개 연속 계좌·200시간 워밍업을 일치시킨다.
  결측은 보간하지 않고 분기 경계에서 계좌 상태를 유지한다. 22계좌는 각각 100만 원으로
  시작하며 전체 기간 단일 누적 계좌가 아니다. 40,896시간 대비 커버리지 88.97%다.
- 원래 돌파/현금/항상 허용하는 중복 대조 `prior`와 기본, 슬리피지 2배,
  수수료·슬리피지 2배, 추가 1시간 지연의 네 조건을 비교한다.
- 모든 조건에서 기존 대비 대응 수익 차이 중앙값 >0, 양수 수익 구간 과반,
  최악 낙폭 ≤10%, 위험 중단 없음, 기본 자연 청산 ≥10회가 탐색 통과 조건이다.
  기존 돌파 88개 결과의 체결과 자산 곡선 전체를 실험 26과 대사한다.
- 이미 반복 관찰한 역사 자료의 탐색이다. 학습 모델/새 홀드아웃/실거래 성과가 아니다.
  `seed-17`은 저장 슬롯이다. 성공하더라도 운영 승격 근거로 삼지 않는다.
- 운영 코드·실거래·설정 서버·DB·배포·버전·커밋·푸시는 변경하지 않는다.

## 결과와 실패 원인

채택하지 않는다. 네 조건 모두 기존 대비 대응 수익 차이 중앙값이 0이며,
위험 중단이 남아 있다. 기본 조건은 22구간 중 20개 순손익이 같고 2개 악화됐다.
평균 이상 거래량 조건은 돌파 신호와 대부분 겹쳤고, 나머지에서도 손실을 피하기보다
나중에 더 높은 가격으로 진입하는 결과가 나왔다. 임계값 배수 탐색은 하지 않았다.

| 조건 | 기존/후보 구간 수익률 중앙값 | 후보 합산 손익 차이 | 후보 최악 낙폭 | 후보 위험 중단 |
|---|---:|---:|---:|---:|
| 기본 | +2.00% / +2.00% | −15,730원 | 10.23% | 4구간 |
| 슬리피지 2배 | +1.11% / +1.11% | −13,744원 | 10.58% | 4구간 |
| 수수료·슬리피지 2배 | +0.19% / +0.19% | −13,676원 | 10.76% | 5구간 |
| 체결 1시간 추가 지연 | +1.69% / +1.69% | −30,462원 | 10.003% | 1구간 |

수익률은 독립 원금 100만 원인 22계좌의 중앙값이지 누적·연환산 수익률이 아니다.
기본 합산 순손익은 기존 +1,189,519원, 후보 +1,173,789원이다.
기본 자연 청산 69회, 수익 구간 12/22개로 기존과 같으며 위험 기준도 통과하지 못했다.

- `block-003`: 진입이 2022-07-28 18:00 UTC에서 7월 30일 13:00 UTC로 밀렸다.
  기준 시가 31,376,000→32,138,000원, 신호 청산이 위험 청산으로 바뀌며 −1,895원.
- `block-005`: 2023-02-15 19:00 UTC 진입이 한 시간 늦어져
  29,726,000→30,013,000원에 진입했다. 이후 자본 경로까지 영향을 받아 −13,836원.
- 나머지 20구간은 순손익이 같다. 추가 지연 조건은 1구간 개선·1구간 악화였지만
  합산은 더 나빴다. 거래량을 확인하면 언제나 진입 품질이 좋아진다는 근거는 없다.

다음 연구는 거래량 배수나 확인 시간을 재조정하기보다, 계속 돌파를 따라가며 비싸게
진입하는 실패를 구분할 수 있는 신호를 먼저 진단해야 한다. 예를 들어 돌파 봉의
상단 꼬리 비중을 사후 오류 군집으로 살펴보고, 충분한 구분이 없다면 해당 필터도
배제한다. 이는 다음 가설이며 현재 결과나 새 홀드아웃의 성공으로 간주하지 않는다.

후속 사후 진단에서 윗꼬리 `(high - max(open, close)) / (high - low)`가
전체 봉 범위의 25%를 초과한 기존 거래는 14건 중 4건 수익, 기존 손익 합계 −60,128원이었다.
나머지는 58건 중 29건 수익, +1,249,647원이었다. 이는 진입 당시 확정 봉으로
분류한 원래 거래 손익이며 필터를 적용한 손익이 아니다. 25% 한 기준만 살폈고
다른 문턱값을 비교하지 않았다. 다음 실험에서는 이 단일 조건의 긴 윗꼬리 진입을
차단하되 거래량 조건과 결합하지 않고, 동일 비용·위험·계좌 구간으로 재평가한다.
이 진단에서 수익 거래 4건도 제외되므로 계좌 경로 재계산 전 개선을 주장하지 않는다.

## 검증 기록

- 352개 백테스트 종료 코드 0. 원래 돌파 88개 전체 결과를 실험 26과 대사했다.
- 최초 실행 `outputs/breakout-volume-27` 이후 docstring의 린트 문자만 수정했다.
  최종 소스 해시를 기록하기 위해 `outputs/breakout-volume-27-verified`에 재실행했다.
  두 실행의 요약 결과가 같고 최종 입력 SHA 및 Python 소스 SHA가 모두 일치한다.
- 현재 봉 거래량 사용, 평균에서 현재 봉 제외, 24봉 경계, 같을 때 차단, 0 평균,
  미래 봉 변경 불변, 추가 대기 없는 체결, 가격 돌파 동시 요구, 기존 26 경로 유지,
  대조 손상 시 성공 기록 금지를 포함한 집중 테스트 6개가 통과했다.
- 전체 테스트 358개 통과, 테스트용 MariaDB 미설정 22개 제외, 커버리지 89.13%.
  Ruff 검사·포맷, mypy 64개 소스, `git diff --check` 통과.
- Spark 읽기 전용 독립 CLI 리뷰 APPROVE, 조치 필요 발견 없음.
  코드 검증 통과와 수익성 기준 실패를 구분하며 운영 변경은 하지 않았다.
