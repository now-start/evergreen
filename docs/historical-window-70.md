# 실험70 — 고정57의2018~2019 역사 구간 검증

실험69에 사전 명시한 범위와 조건을 유지한다. UTC2018-01-01~2020-01-01,
준비200시간, 계좌당100만원,57 후보 하나와 원 돌파·현금·매수보유를 비교한다.

연속 블록으로 나눈다. 각 블록 준비200봉 이후의 모든 시간을 평가하고 전체17,520시간
대비 커버리지를 표시한다. 가격이나 수익을 보고 블록을 제외하지 않는다.
과거 역사 구간 점검이지 전진 검증이나 다중 탐색을 보정한 홀드아웃이 아니다.
기존2022~2026의 지연 실패가 없어지지 않으며 운영 승격·설정·DB·배포 변경은 없다.
`mle-workflow`의 사전 고정·자료 품질·재현 절차를 적용하고 독립 리뷰는 생략한다.

```bash
.venv/bin/python -m evergreen.research fetch --start 2017-12-23T16:00:00Z --end 2020-01-01T00:00:00Z --output data/historical-70-2018-2019-public
.venv/bin/python -m evergreen.research.experiments.historical_window --source data/historical-70-2018-2019-public --output outputs/historical-window-70
```

최초 제한 환경 수집은 DNS 오류로 종료해 실패 기록을 보존했다.
허용된 공개 API 접근으로 새 디렉터리에 다시 수집했고, 품질 실패 결과는
원본 요청·봉을 검증한 뒤 공백과 요청 실패를 구분한다. 기존 실패 폴더를 덮어쓰지 않았다.

중단 계좌는 세 비용 조건 모두 `block-000`이다. 기본/지연 포함 네 결과를
`observe`/`first_breach`로 관찰 재실행해 전체 JSON을 다시 일치시켰다.
기본 조건은2018-01-04 20 UTC에22,546,000원 시가를 기준으로 매수했다.
01-06 02시 시가28,561,000원에서 계좌 고점1,264,889.917862원을 기록한 뒤,
03시 종가25,317,000원에서1,121,221.884222원으로11.3581% 떨어졌다.

이후 위험 매도로 최종1,120,027.042005원, 최대낙폭11.4526%가 됐다.
원금보다12% 많아도 고점 대비 한도를 넘었으므로 중단하는 정책이다.

지연 조건은01-05 13시 신호로 이미 매도를 예약해 이 포지션에서 먼저 빠져나왔고,

지연을 늘리라는 권고가 아니라, 상태·진입 가격·청산 시점에 따라 결과가 달라진 관측이다.

최대TR조차 작았다. 과거 평균 또는 최대 변동폭이 미래 손실을 보장하지 못한다.

## 후속71 사전 계획 — 청산 여유에 직전24봉 최대TR 사용

수익 개선을 확정하지 않는다. 평균 변동폭이 큰 단기 충격을 충분히 반영하지 못한다는
실패를 바탕으로 후보 `liquidation-buffer-tail24` 하나만 평가한다.

- 57의 청산 여유 계산에서 **직전24봉 평균TR을 같은24봉 최대TR로 대체**한다.
  현재 신호 봉은 제외하고 각 TR은 고저폭·이전종가와 고가/저가 차이의 최댓값이다.
  첫 TR의 이전종가를 포함한26개 봉을 요구한다.24/48/168 또는 분위수 검색은 하지 않는다.
- 대기 가격은 `max(0, 현재 확정 종가−(1+추가 지연 시간)×직전24봉 최대TR)`이며,
  이를 기존 수수료·슬리피지·수량으로 순청산 평가해 계좌 고점의90% 이하면 매도를 예약한다.
  한 번 예약된 청산의 유지, 매시간 평가와 다음 시가/추가1시간 체결은 기존57과 같다.
- 진입168시간·전액 거래·진입 예산·초기 손절·추세24시간·채널 리셋·위험 한도는 바꾸지 않는다.
  진입/추적 손절의 평균TR은 유지한다. 최대TR은 청산 여유 계산에만 적용한다.
- 가설은 이전의 큰 변동을 더 오래 반영해 위험 초과 전에 빠져나오는 것이다.
  반례는 너무 일찍 팔아 수익을 줄이는 것, 이후 재진입 경로의 악화,
  이전 최대보다 더 큰 충격을 여전히 놓치는 것이다.10% 손실 보장을 주장하지 않는다.
- 70의2018~2019·13계좌와67의2022~2026·22계좌를 변경 없이 모두 재평가한다.
  각 구간의 원 돌파·현금·57을 대조로 재현한다(35계좌×4조건×3전략=420개 JSON).
  후보 포함560개 손익을 검증하며 계좌 식별자에는 구간을 포함해 중복을 방지한다.
- 네 조건과 공통 게이트를 **각 구간별로** 유지한다. 합친 수치만 좋아져도 통과시키지 않는다.
  두 구간 모두 이미 관측했으므로 이는 후속 탐색이지 새 미관측 검증이 아니다.
  이번70의 결과를 보고 만든 후보를70에서 사전 검증됐다고 표현하지 않는다.
- 과거 최대의 엄격한 봉 범위·현재/미래 봉 제외·원래 지연 신호·기본값 재현·
  매도 예약 유지·진입 예산 불변을 테스트한다. 실거래·설정·DB·버전·배포·커밋·푸시 변경 없음.
