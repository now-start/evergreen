# 실험 39 — 거절한 돌파의 추격 진입 차단

## 사전 고정 계획

[실험38의 후속 계획](breakout-tr-compression-38.md)에 사전 명시한 조건을 그대로 구현한다.
변동 폭의 방향을 바꿔도 늦은 진입과 큰 수익 기회 누락이 남았으므로, 실험37의
TR24>TR168 진입을 유지하면서 거절 이후의 계좌 상태 처리만 바꾼다.

- 후보 `expansion-rejection-latch`. 현금·예약 주문 없음 상태에서 원래 돌파가 매수를
  제안했지만 필터가 거절하면 그 신호 이전168봉 최고가를 고정 기록한다.
- 확정 종가가 고정 기준보다 높은 동안 신규 매수 차단. 종가가 기준 이하가 되면 해제하고
  같은 봉도 원래 신호·당시 필터로 재평가한다. 창 이동·TR 변화·시간 만료로 해제하지 않는다.
- 신호 봉 고가는 기준에서 제외한다. 원래 돌파 신호가 없을 때의 필터 불허는 기록하지 않는다.
  보유·예약 주문 대기 중 기록을 만들지 않으며, 독립 계좌 시작마다 기록이 없다.
- 원래168시간 최고가×1.001 진입·48시간 저점 청산·10% 영구 위험 중단 유지.
  원래 전략/37/38에는 새 옵션을 적용하지 않는다. 매수 거절·체결 수량도 후보 자신의 상태 사용.
- 동일 원자료SHA·200시간 워밍업·22개 독립 연속 계좌·각 원금100만 원,
  36,384/40,896시간(88.97%), 내부 분기 경계 상태 유지, 결측 보간 없음.
- 다음 시가 전액 체결, 양쪽 각각 수수료0.05%·슬리피지0.1%, 최소5천 원·수량1e-8.
  슬리피지2배·비용2배·추가1시간지연까지4조건. 낙폭 중단은 손실 상한 보장 아님.
- 기존·현금·prior·37·38·후보 총528회, 기존/37/38의264개 전체 JSON 재현 요구.
- 모든 조건에서 기존 대비 대응 수익률 차이 중앙값>0, 수익 구간 과반, 최악 낙폭≤10%,
  위험 중단 없음, 기본 자연 청산10회 이상. 조건을 결과에 맞게 완화하지 않는다.
- 큰 상승의 시작을 거절하면 이후 수익 기회를 계속 잃을 수 있다. 추격 차단이 더 좋다는
  가정은 하지 않는다. 이미 본 자료의 탐색이며 새 홀드아웃/딥러닝 학습/실거래 성과 아님.
  독립 계좌 손익 합계는 단일 원금 누적·연환산 수익이 아니다.
- 실거래·Config Server·DB·배포·버전·커밋·푸시 변경 없음.

## 다음 사전 명시 실험 40 — 진입가 기준 고정 손절

진입 필터와 거절 기록을 제거하고 원래 돌파 진입으로 돌아가 **초기 불리한 가격 이동**을
별도로 제한한다. 실험34의 고점 추적은 수익 추세를 잘게 나눴고, 실험35~36의 이익 후
활성화는 처음부터 하락한 거래를 바꾸지 못했다. 다음 후보는 추적하지 않는 고정 기준이다.

- 후보 하나 `entry-stop-tr24`: 실제 매수 기준 시가−3×진입 신호 이전24봉 평균 TR을
  매수 체결 때 고정한다. TR은 기존 공통 함수로 신호 봉 제외·첫 이전종가 포함하여 계산한다.
- 실제 체결 이후 확정 종가가 기준 미만이면 다음 시가 매도한다. 동률은 매도하지 않는다.
  진입 TR이0이면 추가 손절 비활성. 기준을 고점·이후 TR 변화로 올리거나 내리지 않는다.
- 체결 지연에서는 원래 신호 시점 TR과 실제 지연 체결 시가를 사용한다. 새 실제 매수마다
  다시 설정하고 매도 후 제거한다. 체결 전·장중 고저 경로로 손절 체결을 추정하지 않는다.
- 24시간·3배는 기존 실험34의 단위를 재사용한 한 후보이며 최적 배수라는 주장이 아니다.
  기준이0 이하라면 양수 가격의 종가가 하회할 수 없으므로 이 추가 손절은 발생하지 않는다.
- 원래48시간 채널 청산·10% 영구 위험 중단은 유지한다. 진입 필터·거절 기록·추적 청산·
  재진입 대기는 결합하지 않는다. 예약 주문/위험 우선/전체 금액 체결 방식은 그대로다.
- 기존·현금·prior·실험39·후보 총440회 비교, 기존/39의176개 전체 JSON 재현을 요구한다.
  동일 자료·계좌·200시간 워밍업·비용·지연·위험·수익성 기준 유지.
- 가격이 반등하기 전 손절하거나 재진입이 늘어 비용이 커질 수 있고, 수익 반납으로 인한
  계좌 낙폭은 여전히 발생한다. 손실 상한이나 개선을 보장하지 않는다. 이번에는 계획만
  고정했으며 구현/실행/실거래 반영은 하지 않았다. 새 홀드아웃이 아니다.
